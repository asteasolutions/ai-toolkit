# 00 · one-time setup
  • ships as one file: harness-projection.mjs
  • wire it once → every command below works
  • needs Node 20+ only — no npm install, no network
00.1

Where the file lives
  • bundled at .claude/skills/setup/scripts/
  • no dependencies
the bundled single file
> ls .claude/skills/setup/scripts/
harness-projection.mjs
00.2

Wire the commands
  • with a package.json: add the harness-setup:sync and harness-setup:check scripts
  • run them with the repo's package manager: prefer packageManager, then one unambiguous lockfile; ask if signals conflict
  • point them at the bundled file:
package.json → "scripts"
{
  "scripts": {
    "harness-setup:sync":  "node .claude/skills/setup/scripts/harness-projection.mjs sync",
    "harness-setup:check": "node .claude/skills/setup/scripts/harness-projection.mjs check"
  }
}
use the repo's package manager npm run harness-setup:sync · pnpm run harness-setup:sync · yarn harness-setup:sync · bun run harness-setup:sync. Use the matching harness-setup:check command afterward. The npm commands shown later in this visual are one concrete example.
no package.json? Skip the scripts. Run Node on the file directly — same tool, same args:
no package.json — call node
> node .claude/skills/setup/scripts/harness-projection.mjs sync
> node .claude/skills/setup/scripts/harness-projection.mjs check
then
  • commit the script (and package.json change, if any)
  • after the first sync, also commit .harness-projection/decisions.json with the generated files
  • day to day: use the detected package-manager commands, or the node … commands above

# 01 · two commands
writes · interactive

sync

> npm run harness-setup:sync
or node …/harness-projection.mjs sync
  • asks when a translation isn't clean
  • regenerates the Copilot side
  • saves answers in .harness-projection/decisions.json
read-only · CI gate

check

> npm run harness-setup:check
or node …/harness-projection.mjs check
  • never writes, never prompts
  • pass → exit 0 · drift → exit 1
  • fails the build if output is stale

No package.json? Use the node … form — see §00.2.

# 04 · warnings & stops
  • fail-closed — almost no soft warnings
  • ambiguity → question (§03)
  • real problems → hard stop
  • two you may hit:
info notice after a sync — a hand edit was undone
i .github/agents/reviewer.agent.md: dropped hand-added tool read/readFile — it comes
  from Claude tool Read. Change the tools list in
  .claude/agents/reviewer.md instead.
what to do
  • you edited a generated file — tool reclaimed it as drift
  • change tools in canonical .claude/agents/… tools list
  • never edit the generated file
a hard stop — the tool won't clobber a file it doesn't own
harness-projection: refusing to overwrite unmanaged file .github/agents/reviewer.agent.md
what to do
  • file sits where a generated one should, but lacks ownership marker (§07)
  • move or delete it, then re-run sync
  • tool never overwrites files it didn't create

# 05 · limitations — claude vs copilot
  • Copilot lacks some Claude capabilities
  • maps what it can · narrows what it must · drops the rest
  • that's why §03 exists
exact →
one-to-one tool maps · never re-asked unless source changes
expanding →
Read / Write each split into ≤3 VS Code tools — you choose (§03.1)
lossy →
PowerShell shares terminal with Bash · WebFetch → web/fetch · LSP → usages + problems
dropped ✕
~30 tools have no equivalent — not granted: SkillTodoWriteWebSearchTask*WorkflowArtifactCron*…
also
  • scoped grants can't be preserved — Bash(npm run *) can only widen or drop (§03.2)
  • skills aren't projected — stay in .claude/skills/; Copilot just points at the same folder
  • MCP tools renamed, not resolved — mcp__server__tool → server/tool
  • keep the same server key in .mcp.json and .vscode/mcp.json

# 06 · what check reports
  • same analysis as sync
  • compares against disk — writes nothing, never prompts
  • your CI gate
pass
> npm run harness-setup:check
Checked 6 Agent Projections and 3 Scoped Instructions; no drift.
exit 0
fail — written to stderr, exit 1
> npm run harness-setup:check
harness-projection: projection check failed:
- drift in .github/agents/reviewer.agent.md
- missing .github/instructions/style.instructions.md
Run `npm run harness-setup:sync` to regenerate.
it fails on
  • hand-edited (drift), missing, or orphaned generated file
  • unresolved or stale decision
  • unconfigured VS Code settings
  • fix: always run sync
